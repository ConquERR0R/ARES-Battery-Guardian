## Run key or elevated task: the trade-off

- **Run key (default, no admin).** Set from Settings by an ordinary user, and starts ARES with normal rights at sign-in. Monitoring, history, notifications, alarms and both protection screens work. ARES **cannot** write the Dell BIOS charge limit in this mode.
- **Elevated task (optional, run `install_startup.bat` once).** Starts ARES with admin rights and no UAC prompt, so the BIOS 90% stop can be re-applied at sign-in.
- **Why this is optional.** Once the BIOS limit has been applied, the firmware enforces it even when ARES isn't running. The elevated task only matters if you want ARES to check and re-apply it automatically.

ARES never keeps both: when the task is present, the Run value is removed. All three entry points (Settings, startup at sign-in, and the `--install-startup` / `--remove-startup` commands) go through the same code.

## Manual Windows 11 test (not yet done: everything above was only tested on Linux)

Use a PowerShell window in the project folder. With the EXE, replace `python main.py` with `.\ARES-Battery-Guardian.exe`.

1. `.venv\Scripts\python -m unittest discover -s tests`. Expect `Ran 105 tests … OK`.
2. Run `python main.py --exit`, then start ARES normally with `.venv\Scripts\python main.py`.
3. Open **Settings → E. Startup**.
   - It should show *Enabled — Registry Run key (current user)* and *✓ Startup registration successfully applied*. It takes up to 3 s after start.
   - If you ran `install_startup.bat` before, it shows *Task Scheduler (elevated)* instead.
4. Check the registry with `reg query HKCU\Software\Microsoft\Windows\CurrentVersion\Run /v ARESBatteryGuardian`.
   - Expect exactly one value: a quoted `pythonw.exe` path, then `main.py`, then `--autostart`.
   - **Task Manager → Startup apps** should list it once.
5. Click **Test startup configuration**. Expect "Result: OK".
6. Untick *Start ARES automatically*.
   - Status becomes *Disabled*.
   - The `reg query` from step 4 says "unable to find".
   - Your other startup apps are unchanged.
   - Tick it again: exactly one value comes back.
7. **Dashboard by default:** sign out and sign back in. Within a few seconds ARES opens the dashboard and the tray icon appears.
8. **Start minimized:** tick *Start minimized in system tray*, then sign out and sign back in. Only the tray icon appears and monitoring runs: the dashboard's last reading time updates when you open it.
9. **Single instance:** while ARES is running, run `python main.py --autostart` again.
   - You get no second tray icon.
   - The existing dashboard comes to the front (stays hidden if *Start minimized* is on).
   - `logs\ares.log` shows "Another instance is running".
10. **Moved program:** quit ARES. Edit the Run value so it points at a path that doesn't exist, for example with `regedit`. Start ARES. Within 3 s, Settings shows the entry repaired, and **Test** says OK.
11. **Persistence:** choose Exit ARES, start ARES again, and check both checkboxes kept their values.
12. **Elevated, optional:** run `install_startup.bat` and accept the prompt.
    - Settings shows *Task Scheduler (elevated)*.
    - The Run value is gone.
    - After sign-in, the dashboard title shows *[Administrator]*.

## Known limitations

- **Nothing here has run on Windows yet.** The registry was an in-memory fake in the tests and Task Scheduler was mocked.
- **Run key timing.** Windows can delay Run-key apps by a few seconds after sign-in. If the taskbar isn't ready yet, the tray icon retries for up to 2 minutes.
- **Settings and an existing elevated task.** Changing startup in Settings without admin cannot edit an elevated task. Turning startup off then needs admin, so run `install_startup.bat` / `--remove-startup` as administrator, or delete the task in Task Scheduler.
- **No PyInstaller rebuild.** The path logic for the EXE (`sys.frozen`) was tested only with mocks. The EXE has not been rebuilt.
