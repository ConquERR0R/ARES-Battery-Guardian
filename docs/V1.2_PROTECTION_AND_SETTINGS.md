# ARES v1.2 – Settings redesign and 90% / 25% battery protection

## Modified files

| File | Change |
|---|---|
| `app/core/strict_lock.py` | Rewritten as `ProtectionPolicy`, with HIGH (≥90%, charger on) and LOW (≤25%, charger off) modes. LOW is checked first, each mode fires once per session, and emergency suppression is saved per mode. |
| `app/ui/lock_window.py` | One shared `ProtectionWindow` for both modes, plus `ProtectionManager`. The manager runs a 5 s idle power check and a 1 s check while a screen is shown, keeps at most one window, plays the alarm, repeats it at the set interval, stops it when the screen clears, and handles the fail-safe and the emergency shortcut. |
| `app/services/sound_service.py` | Separate high and low alarms with different Windows default sounds. WAV files are checked (RIFF/WAVE), `stop()` ends playback, and `AlarmPlayer` is the default player. |
| `app/ui/settings.py` | Rewritten into sections A–F. Every control saves on change (spin boxes after a 0.4 s pause) and emits `setting_changed`. Browse and Test buttons work for each alarm. Thresholds are validated before saving. Controls that can't work on this PC are disabled and the reason is shown. |
| `app/ui/theme.py` (new) | Fusion style with a dark palette and visible check-box indicators. This fixes the controls that looked dead (see "Settings fix" below). |
| `app/ui/background_app.py` | Runs settings migration, owns the `ProtectionManager`, and routes each saved setting to the protection manager or the monitoring worker. Worker updates are debounced. |
| `app/ui/main_window.py` | Removed the CSV export handler. Settings now connects through `setting_changed`. Closing the window flushes pending edits. |
| `app/ui/dashboard.py` | Removed the three "Export … CSV" buttons from History. No data was removed. |
| `app/database/database.py` | New settings defaults and `migrate_settings()`, which copies the old alert sound to the high alarm and the old sound toggle to the sound master switch. |
| `app/services/notification_service.py` | The maximum-charge alert no longer plays a second sound when High Battery Protection is on. |
| `app/core/monitor_service.py` | Its test sound now uses the high-alarm settings. |
| `main.py` | `apply_theme()` added. `--unlock` and `--disable-lock` now cover both modes. |
| `app/__init__.py` | Version 1.2.0. |
| `README.md` | Protection section, Settings and test count updated. |
| `tests/test_protection.py` (new), `tests/test_strict_lock.py`, `tests/test_core.py` | New tests added and existing tests updated for the new API. |

`report_service.export_*_csv` and every database table (samples, sessions, events, health) are unchanged.

## Settings fix (root causes)

1. **Style sheet.** The old style sheet had `QWidget { background }` plus border rules on spin boxes and combo boxes. Those rules force Qt's style-sheet renderer, which on Windows 11 can leave check-box indicators, spin arrows and combo arrows invisible. **Fix:** Fusion style with a dark palette, no style-sheet rules on input widgets, and explicit check-box indicators.
2. **Disabled controls.** A disabled control looked identical to an enabled one. For example, *Stop charging automatically* is disabled when no Dell cctk interface is detected, but still looked clickable. **Fix:** disabled controls are now visibly greyed out, with the reason shown.
3. **Saving.** Nothing was saved until **Save settings** was pressed, so changes were lost on close and only reached the services on Save. **Fix:** every change is saved and pushed to the services immediately.

## Manual test plan on the E7470 (Windows 11)

Run these from the project folder:

1. `.venv\Scripts\python -m unittest discover -s tests`. Expect `Ran 94 tests … OK`.
2. Start ARES with `python main.py --exit`, then `python main.py`.
3. **Settings:**
   1. In each section, click every check box and change every spin box.
   2. Close the dashboard, reopen it from the tray, and confirm the values stayed.
   3. Choose Exit ARES, start it again, and confirm the values are still there.
4. **Sound:**
   1. Click **Test alarm** in sections B and C. You should hear two different sounds.
   2. Use **Browse…**, pick a `.wav` from `C:\Windows\Media`, then click **Test alarm**. It plays that file.
   3. Type a wrong path. Settings shows "File not found", and Test plays the default sound.
5. **Low protection (fast check):**
   1. Set C → threshold to a value just above the current battery %.
   2. Unplug the charger.
   3. Within about 5 s you should get the amber full-screen *LOW BATTERY* screen and the alarm.
   4. Plug the charger in. The screen disappears within about 1 s.
   5. **Events** shows an ON and an OFF entry.
6. **High protection (fast check):**
   1. Set B → threshold to a value just below the current battery %.
   2. Plug in the charger. You should get the red *BATTERY LIMIT REACHED* screen and the alarm.
   3. Unplug. The screen and the alarm stop.
7. **Repeat interval:** set B → Repeat to 1 min and trigger the screen. The alarm plays again after 1 min and stops when you unplug.
8. **Emergency:**
   1. With a screen up, click it and press Ctrl+Alt+Shift+U. It closes.
   2. Trigger it again and run `python main.py --unlock` from a terminal. It closes.
   3. Ctrl+Alt+Del and Task Manager stay available the whole time.
9. **Dashboard closed:** close the dashboard with X, then repeat step 5. The screen still appears.
10. **CSV buttons:** the History tab has no Export buttons, and its graph and sessions still show your data.
11. Restore your real thresholds (B = 90, C = 25) afterwards.

## Windows-specific limitations (not verified; tests ran on Linux only)

- **Full-screen and on-top behaviour** was checked only with Qt's offscreen platform.
  - Windows can refuse to give focus to a window from a background app. If the shortcut doesn't respond, click the protection screen first.
  - The window covers the primary monitor only.
  - Full-screen games or other always-on-top apps may sit above it.
- **WAV playback (`winsound`)** was mocked in the tests.
  - The default files (`Windows Exclamation.wav`, `Windows Battery Low.wav`) are standard on Windows 11. If either is missing, the Windows sound alias is used instead.
  - Long WAV files keep playing until they finish or the screen clears.
- **AC detection** uses `GetSystemPowerStatus` and the battery IOCTLs. Neither was exercised on real hardware.
- **Windows' own low-battery actions** at critical battery levels (hibernate or shut down) still apply and take precedence.
- **PyInstaller:** no new third-party packages were added (`winsound` is in the standard library, and QtTest is used only by the tests), so the existing spec should still work. The EXE has not been rebuilt, as requested.
